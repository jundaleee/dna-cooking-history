# 프로토콜 5. 사전 고정, 원자료 수령, 독립 재계산

결과를 본 뒤 규칙을 바꾸지 않았음을 제3자가 확인할 수 있게 한다.

## 결과 전에 고정할 것
- 단계마다 가설과 반증 조건(예: "대조 칸이 오르면 측정은 정상 증폭이 아니다")
- 판정 규칙의 숫자(오름 기준, 효율 범위, 정상 증폭 점검 문턱, 제외 규칙)
- 분석 코드와 설정, 판 배치표
- 대조 칸이 실패했을 때의 행동(예: 온도·시간 판정을 보류한다)

고정은 저장소에 커밋하고 커밋 시각을 기록으로 삼는다. 코드·설정·입력 파일의 해시값은 도구로 남기고, 실측 분석 직전에 같은지 확인한다:

```bash
python -m rne.pipeline.freeze make --settings settings.json --out freeze/manifest.json
python -m rne.pipeline.freeze verify freeze/manifest.json
```

## 원자료를 받을 때
받는 즉시, 값을 열어 보기 전에 `templates/receipt_template.json` 형식으로 적고 커밋한다.
- 파일마다 이름, 크기, sha256(`sha256sum <파일>`), 받은 시각, 받은 경로
- 고정 전에 결과를 본 사람과 본 것(기기 화면 사진 등). 없으면 빈 목록
- 눈가림: 판정 규칙을 통과하기 전에는 시료 칸의 값을 온도·시간과 연결하지 않는다. 대조 칸 판정과 곡선 모양의 집계만 먼저 본다(`python -m rne.qc.normal_range ... --aggregate-only`)

## 규칙을 바꿔야 할 때
바꾼 사실, 이유, 바꾼 시각을 결과 문서에 적고, 바꾸기 전 규칙의 판정도 함께 낸다. 결과를 본 뒤 정한 기준은 그렇다고 밝힌다.

## 독립 재계산
최종 계산을 다른 사람이 **원 코드를 보지 않고** 같은 원자료에서 다시 계산한다.
1. 재계산하는 사람은 대조하기 전에 자기 숫자를 먼저 커밋한다
2. 두 결과를 대조해 어긋난 곳마다 원인(설정 차이, 정의 차이)을 찾는다
3. 원인과 처리(같은 설정이면 맞는지, 정의를 본문에 적었는지)를 표로 남긴다
